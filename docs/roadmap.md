## Этап 1 — Detector Engine + Law Base
**Статус:** 🔲 Не начат

### Цель
Каждый детектор работает, протестирован, синхронизирован с базой критериев.

### Принцип
**Один детектор = одна запись в Law Base = два теста (нарушение + соответствие)**

### Задачи — Law Base
- [ ] Определить схему YAML для записи критерия (id, name, severity, detector, legal_ref, fine, fix, enabled)
- [ ] Заполнить `law_base/blocks/A.yaml` — блок А (документы на сайте)
- [ ] Заполнить `law_base/blocks/B.yaml` — блок Б (механика согласия)
- [ ] Заполнить `law_base/blocks/C.yaml` — блок В (cookies и аналитика)
- [ ] Заполнить `law_base/blocks/D.yaml` — блок Г (уведомление РКН)
- [ ] Заполнить `law_base/blocks/E.yaml` — блок Д (локализация и инфраструктура)
- [ ] Заполнить `law_base/blocks/F.yaml` — блок Е (фото сотрудников)
- [ ] Заполнить `law_base/blocks/G.yaml` — блок Ж (организационные меры)
- [ ] Создать `law_base/sources.yaml` — источники законов

### Задачи — Detector Engine
- [ ] Реализовать `scanner/detectors/base.py` — базовый класс детектора
- [ ] Реализовать фабричный паттерн в `scanner/engine.py` (dispatch по method, не по id)
- [ ] Реализовать `scanner/playwright_wrapper.py`
- [ ] Реализовать детекторы блока А (только статически детектируемые)
- [ ] Реализовать детекторы блока Б
- [ ] Реализовать детекторы блока В
- [ ] Реализовать детекторы блоков Г-Ж (только статически детектируемые)

### Задачи — Тесты
- [ ] Создать тестовые HTML-fixtures для каждого детектора
- [ ] Написать тест "нарушение" для каждого детектора

## Этап 2 — Scanner + Report Engine + минимальный UI
**Статус:** 🔲 Не начат

### Цель
Рабочий продукт который можно показать реальному пользователю.

### Задачи — Scanner
- [ ] Реализовать `scanner/engine.py` — прогон всех детекторов по URL
- [ ] Обработка ошибок на уровне каждого детектора (один упал — остальные продолжают)
- [ ] Поддержка одиночного URL и списка URL

### Задачи — Report Engine
- [ ] Реализовать `report/engine.py` — формирование отчёта из результатов
- [ ] Формат JSON
- [ ] Формат HTML (читаемый, без технического жаргона)
- [ ] Разделение: нарушения / рекомендации

### Задачи — API
- [ ] Реализовать `api/main.py` на FastAPI
- [ ] Эндпоинт POST `/scan` — принимает URL, возвращает отчёт JSON
- [ ] Эндпоинт GET `/report/{id}` — получить отчёт по id

### Задачи — UI
- [ ] Минимальный React UI: поле URL + кнопка + отображение результата
- [ ] Отображение нарушений: что, где, штраф, как исправить
- [ ] Отображение рекомендаций отдельно от нарушений

### Результат
Пользователь вводит URL в браузере — получает понятный отчёт.
