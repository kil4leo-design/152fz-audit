## Этап 2 — Scanner + Report Engine + минимальный UI
**Статус:** 🔲 Не начат

### Цель
Рабочий продукт который можно показать реальному пользователю.

### Задачи — Scanner
- [ ] Реализовать `scanner/engine.py` — прогон всех детекторов по URL
- [ ] Обработка ошибок на уровне каждого детектора (один упал — остальные продолжают)
- [ ] Поддержка одиночного URL и списка URL

### Задачи — Report Engine
- [ ] Реализовать `report/engine.py` — формирование отчёта из результатов
- [ ] Формат JSON
- [ ] Формат HTML (читаемый, без технического жаргона)
- [ ] Разделение: нарушения / рекомендации

### Задачи — API
- [ ] Реализовать `api/main.py` на FastAPI
- [ ] Эндпоинт POST `/scan` — принимает URL, возвращает отчёт JSON
- [ ] Эндпоинт GET `/report/{id}` — получить отчёт по id

### Задачи — UI
- [ ] Минимальный React UI: поле URL + кнопка + отображение результата
- [ ] Отображение нарушений: что, где, штраф, как исправить
- [ ] Отображение рекомендаций отдельно от нарушений
- [ ] Выбор блоков проверки (А-Ж) или полная проверка — UI переключатель

### Результат
Пользователь вводит URL в браузере — получает понятный отчёт.

## После MVP (backlog)

- **Law Monitor** — автоматический мониторинг изменений законов
  - Источник: publication.pravo.gov.ru (публичное API без ключа + RSS)
  - Компоненты: fetcher, parser, analyzer, notifier, scheduler
  - Расписание: раз в месяц через GitHub Actions
  - Процесс: автомониторинг → AI-анализ → подтверждение оператором → обновление Law Base
  - Детали: см. decisions.md → раздел "Law Monitor — детальная архитектура" 
- Auth + Billing — подписка, разовая оплата за отчёт
- История проверок с динамикой
- Десктопная упаковка (Electron / Tauri)
- Миграция БД SQLite → PostgreSQL
- Название продукта на кириллице
