## Протокол начала каждой сессии (обязателен)

Перед любой работой прочитай файлы в этом порядке:

1. `docs/START.md` — текущий статус, что сделано последним, следующий шаг
2. `docs/decisions.md` — все принятые решения: продукт, стек, архитектура, правила
3. `docs/architecture.md` — модули, потоки данных, реестр детекторов, форматы

После прочтения:
- Сообщи: какой этап активен, что сделано последним
- Спроси: что делаем в этой сессии
- **Не начинай работу до подтверждения**

## Правила (без исключений)

- Не поддакивать. Критически оценивать предложения.
- Фантазия = ошибка. Только факты из файлов репо и контекста сессии.
- Штрафы и нормы 152-ФЗ — только из первоисточника (КонсультантПлюс), не из статей.
- При сомнении в юридической части — сообщать явно, не домысливать.
- Один модуль = одна сессия.
- Код сдаётся только с зелёными тестами.
- Один логический блок изменений = один коммит.

## Процесс написания кода

1. Прочитать закрепощённые файлы (law_base/blocks/*.yaml, architecture.md)
2. Написать черновик
3. Провести полный независимый аудит построчно
4. Исправить найденное
5. Запустить тесты: `pytest tests/ -v`
6. Только после зелёных тестов — коммит

**Частичное выполнение = ошибка.**
Если задача затрагивает несколько файлов — обновить все в одном коммите.

## Стек

Python 3.12, Playwright, BeautifulSoup4, FastAPI, Pydantic v2, PyYAML, pytest

## Текущая структура детекторов

Базовый класс: `scanner/detectors/base.py` — `BaseDetector(ABC)`
Движок: `scanner/engine.py` — `DetectorEngine` (фабричный паттерн, dispatch по `detector.method`)
Реестр методов: см. `docs/architecture.md` → таблица "Реестр методов"
Law Base: `law_base/blocks/*.yaml` — единственный источник правил и параметров

Активация нового детектора в `scanner/engine.py` — два шага одновременно:
  1. Раскомментировать import
  2. Раскомментировать строку в DETECTOR_REGISTRY
